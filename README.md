# Автоматическая публикация курса «Испанский через истории»

Готовая система без установки Python и без отдельного сервера. Всё работает в GitHub Actions на Node.js, который GitHub предоставляет автоматически.

## Расписание

- 07:00 по часовому поясу `Europe/Moscow` — утренний урок и аудио.
- 14:00 — дневная практика и аудио.
- В дни 7, 14, 21, 28 и 30 перед утренним уроком публикуется изображение.
- `data/state.json` защищает от повторов после перезапуска.

## Что уже готово

- Тексты всех 30 утренних уроков.
- Тексты всех 30 дневных практик.
- В День 29 добавлена конструкция `Vivo en…`.
- Пять изображений уже лежат в `images/`.
- Код расписания и тестовый ручной запуск.

## Что нужно сделать

### 1. Добавить 60 аудиофайлов

Распакуйте скачанный архив аудио и переименуйте файлы точно так:

- утро: `audio/morning/day01.mp3` … `day30.mp3`;
- день: `audio/practice/day01.mp3` … `day30.mp3`.

В каждой папке есть подсказка со всеми именами.

### 2. Загрузить проект в GitHub

Создайте новый публичный репозиторий, например `spanish-course-publisher`, и загрузите **содержимое этой папки**, включая скрытую папку `.github`.

Проще всего: GitHub → Add file → Upload files → перетащить все папки и файлы → Commit changes.

### 3. Создать Telegram-бота

В `@BotFather` создайте бота, скопируйте токен, добавьте бота администратором канала и разрешите ему публиковать сообщения.

### 4. Добавить GitHub Secrets

Репозиторий → Settings → Secrets and variables → Actions → вкладка Secrets → New repository secret:

- `BOT_TOKEN` — токен Telegram-бота;
- `CHANNEL_ID` — username канала, например `@spanish_history`, либо числовой ID.

### 5. Добавить Variables

Там же → вкладка Variables:

- `START_DATE` — дата первого урока в формате `YYYY-MM-DD`, например `2026-08-03`;
- `TIMEZONE` — `Europe/Moscow`.

### 6. Разрешить сохранение состояния

Settings → Actions → General → Workflow permissions → выбрать **Read and write permissions** → Save.

### 7. Проверить комплект файлов

Actions → `Publish Spanish course` → Run workflow → `slot: check` → Run workflow.

Зелёная галочка означает, что на месте все 60 MP3 и 5 изображений.

### 8. Провести две тестовые публикации

Сначала запустите:

- `slot: morning`, `day: 1`;
- затем `slot: practice`, `day: 1`.

Тестовые запуски не меняют `state.json` и не мешают официальному старту.

### 9. Запуск

После успешного теста больше ничего нажимать не нужно. В дату `START_DATE` GitHub опубликует День 1 в 07:00 и практику в 14:00.

## Важные замечания

GitHub Actions проверяет расписание каждые 10 минут. Публикация обычно появляется в пределах нескольких минут после 07:00 или 14:00; иногда GitHub может задержать бесплатный cron. Скрипт допускает окно до 07:49 и 14:49, а защита состояния не позволяет отправить урок повторно.

Не удаляйте `data/state.json` после старта. Не запускайте ручной тест в основной канал, если не хотите увидеть тестовый урок там.
